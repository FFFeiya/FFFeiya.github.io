Unreal 5 源码阅读笔记，大纲

2026.01.24 UnrealSourceRuntimeC++Engine

关键词：Unreal Engine 5.6、源码、C++、Runtime、Engine、引擎开发和优化

Engine/Source 顶层结构

  • Runtime/：打进游戏、运行时用到的模块
  • Editor/：编辑器专用（UnrealEd、各种资产编辑器、蓝图编辑器）
  • Developer/：开发期工具与基础设施（DDC、性能分析、源控、Cook 辅助）
  • Programs/：独立可执行工具源码（UBT/UHT/ShaderCompileWorker/UnrealPak/Insights…）
  • ThirdParty/：第三方库接入（压缩、图像、音频、网络、平台 SDK…）

Runtime/ 里的“骨架模块组”（按用途分区）

1) 基础设施层（“C++ 标准库 + 平台层 + 日志/任务/模块系统”）

  • Core/：容器、字符串、内存、线程、日志、配置、模块加载
  • Projects/：.uproject / 插件 / 项目描述与加载
  • TraceLog/：追踪与事件记录（和 Insights 相关）
  • ApplicationCore/：窗口/输入/平台事件（更贴近 OS）
  • Json/、JsonUtilities/：JSON 解析与反射映射
  • PakFile/：Pak 包读写（资源打包与运行时加载底座之一）
  • AssetRegistry/：资产注册表（编辑器与运行时都会依赖一些能力）

2) 对象系统与世界框架（“UObject、反射、GC、世界与Actor生命周期”）

  • CoreUObject/：UObject/UClass/反射/序列化/GC
  • Engine/：UWorld、Actor/Component、Tick、GameFramework 基本件
  • GameplayTags/：GameplayTag（GAS/系统标记常用）
  • GameplayTasks/：GameplayTask（GAS 的 task、AI 行为等会用）
  • PhysicsCore/：物理抽象与基础类型（Chaos 也会挂钩）
  • NetCore/：网络底层公共件（复制系统会用到一些通用结构）

3) 渲染与图形（“从 API 抽象到真正出画面”）

  • RHI/：Render Hardware Interface（图形 API 抽象层：DX12/Vulkan/Metal…的统一接口）
  • RenderCore/：渲染核心通用逻辑（资源、渲染线程交互等）
  • Renderer/：默认渲染器实现（很多你听过的渲染特性在这附近落地）
  • RHICore/（部分版本存在）：RHI 辅助/公共部分
  • SlateCore/、Slate/：UI 框架底座与实现（编辑器和运行时 UI 都靠它）
  • UMG/：更上层的 UI（蓝图 UI / Widget）

记忆钩子：“RHI 是‘我能对显卡说话’，RenderCore 是‘说话的语法’，Renderer 是‘要说什么画面’。”

4) 网络（“连接、复制、RPC、会话”）

  • Networking/、Sockets/：套接字与网络基础设施（UDP/TCP等封装）
  • OnlineSubsystem/（以及 Online 子模块）：账号、会话、匹配等
  • NetCore/ + Engine/：复制/RPC/ActorChannel 等大量逻辑其实在 Engine 里

5) 音频（“混音、设备、格式”）

  • AudioMixer/：现代音频混音核心
  • Sound…（很多相关内容也在 Engine/ 下的 Audio 目录结构里）

6) 物理（“Chaos 系列”）

  • Chaos/、ChaosCore/
  • PhysicsCore/（前面提到的抽象层）

7) 动画（常见落点）

动画相关大量在 Engine/ 以及一些专门模块/目录中（例如 AnimGraphRuntime 等可能在 Runtime 下以模块形式存在，具体取决于版本与裁剪）。

Editor / Developer / Programs：你要怎么“按需看”

  • Editor/：“功能大多在 Editor/，运行时不带；但会和 Runtime 的资产系统/反射系统强耦合。”

  • Developer/： DDC、Cook 管线、命令行工具支持、性能诊断 。

  • Programs/：“UBT/UHT/ShaderCompileWorker/UnrealPak 是啥、编译和打包怎么跑”。

目录的最小路线

  1. Runtime/Core（看引擎怎么活：模块/日志/容器/线程）
  2. Runtime/CoreUObject（看反射/GC：UCLASS/UPROPERTY 的落点）
  3. Runtime/Engine（看世界：UWorld、Actor/Component 生命周期、Tick）
  4. Runtime/NetCore + Engine 网络相关（看复制/RPC 是怎么挂在 Actor 上的）
  5. Runtime/RHI → RenderCore → Renderer（看渲染分层）
  6. Runtime/Slate/UMG（看 UI 分层）
