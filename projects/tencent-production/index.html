概览

2026 年 5 月到 8 月，我在腾讯 IEG 内容生态部《虚环》项目组做游戏客户端开发实习生，项目使用 Unity。工作落在三层：项目主干上的运行时功能与调试工具、给策划用的配置编辑器、给 UI 生产用的自动化管线。

20+项 Unity 主干上的功能任务
5类节点，覆盖 Excel↔蓝图双向编辑
6类处理动作的图层合并计划

问题

内容型项目的瓶颈往往不在“功能做不出来”，而在内容生产和验证的成本：

  • 策划的配置分布在多级 Excel 里，有跨表逻辑和蓝图引用，改一处要在几张表之间来回核对
  • 运行时出了问题，复现需要构造特定的日程、角色状态或比赛结果，手工走一遍很慢
  • UI 从 PSD 到 Prefab 的还原是重复劳动，隐含的图层处理规则只存在于人的经验里

我的角色

实习生，但承担的是独立的功能任务。需要说清楚的边界：

  • 独立负责：主干上的 GM、Cutscene、UI 应用层、剧情相关的 20 余项功能；Excel↔可视化蓝图的双向编辑专项；养成配置的节点化；UI 内容生产管线
  • 共同建设：编辑器的蓝图体系——我负责近期的扩展与视图集成，不是从零独立完成
  • 参与接入：配置在运行时的执行由一套统一执行器负责，我做的是渲染侧适配、runtime bridge 和预览入口，不是它的整体架构
  • 不属于我：配置编辑器的内核

约束

  • 不能破坏既有的 Excel 数据链路：原表仍然是其他流程的输入，未知列必须原样保留
  • 多表、多行聚合、跨蓝图引用，导入必须能诊断出缺列与别名
  • 生成式步骤（AI 处理 PSD 图层）的结果不稳定，需要可审查、可回退
  • 实习周期有限，产出要小粒度、可审查

做法

Unity 主干：运行时功能与排查工具

  • GM 调试面板：把日程跳转、角色状态、比赛结果等高频调试场景做成面板与批处理（录制、列表、编辑）
  • Cutscene 演出：过场编辑器的轨道能力扩展，包括场景脚本关键帧、灯光轨道对 layer 与材质参数的控制
  • 排查与性能：语音配置的链路追踪工具、剧情性能跑测工具、对象池审计

配置编辑器：Excel ↔ 可视化蓝图

把日程、逻辑列表、条件判断、剧情引用、对话气泡抽象为 5 类节点，打通：

扫描与诊断 → 分组导入 → 可视化编辑 → 反向抽取 → 写回原表 + 备份

另一条线是把训练、直播、角色状态等养成配置节点化，沉淀可复用的节点库，并接入 Unity 侧的只读同步和运行时验证。编辑器基于 Electron / React / TypeScript。

UI 生产管线：PSD → Unity

  • 应用层：Button 事件自动绑定、Slot 预制体化、多实例差异保留的状态绑定
  • 管线：把原本隐含在处理链里的图层合并规则，迁移成“AI 生成计划 → 人工可审查 → 执行器回放”的显式计划数据，支持 6 类处理动作
  • 质量：图层树摘要、回归样例、Smoke Test，保留旧链路作为回退

Agent Skill

把剧情结构化生成、PSD 批处理、UI 批注精修这些重复的研发任务封装成 Skill，用 Schema、稳定 ID 和阶段验收约束模型输出；在组内做过 AI 提效与 Skill 开发的分享。

工程决策

  • 先冻结数据边界再写代码。 双向编辑专项经历过一次返工：逻辑子图最初是独立文件，后来改为内联，并系统清理了旧文件、导航和校验。教训是单一事实源、文件颗粒度、跨蓝图引用和保存原子性，要在大批量实现之前定下来。
  • 把隐式规则变成可审查的数据。 图层合并从启发式代码改成计划文件之后，出错时能看到“计划是什么”，而不只是“结果不对”。
  • 给生成式步骤留人工控制点。 计划可保存、可回放，执行有回退，验收分阶段。
  • 区分“代码完成”和“验收完成”。 我在文档里固定使用已实现、已测试、观察期、待联调这样的状态词，避免把提交等同于交付。

结果与状态

  • Excel↔蓝图的导入、内联编辑、反向抽取、写回与备份已实现；完整的异常数据往返与 Unity 对齐验收，到 2026 年 8 月初我整理记录时还没有全部完成
  • 养成配置节点化的主批次已实现；统一执行器在真实场景下的完整端到端验收当时也未完成
  • 图层合并计划的核心实现完成，进入真实 PSD 样本的观察期，旧链路仍作为回退保留
  • 主干上的功能任务均有实现日志、修改报告或测试记录

我学到的

  • 工具的用户是具体的人：策划、音频、美术和客户端各有不同的“改完之后怎么确认”
  • 边界意识和实现能力同样重要：说清楚哪部分是自己的、哪部分是共建、哪部分只是接入
  • 状态要诚实。“代码写完了”不等于“可以放心用了”
